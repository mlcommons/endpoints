# The 2026-10-C1 cohort: what it checks, and what it cannot yet

`config/cohorts/2026-10-C1/` is the MLPerf Endpoints submission cohort for the
`2026-10-C1` round, expressed in the `inference_endpoint.validation` dialect:

```
2026-10-C1/
├── cohort.yaml         the manifest: `ruleset_dir: ruleset`
├── valid_refs.yaml     every fact a row may name, as its document spells it
├── pareto.yaml         per-pareto checks
├── point.yaml          per-run checks
├── system.yaml         per-system checks
└── ruleset/            this cohort's catalog: models.yaml + datasets.yaml
```

Run it against a submission with:

```bash
python -m inference_endpoint.validation \
  src/inference_endpoint/config/cohorts/2026-10-C1 \
  path/to/submission
```

## What the cohort checks

- **Per run** (`point.yaml`): the §8.3 disclosure set is present; the cohort and
  seed declarations are well-formed and match published set A (membership, the
  §4.6 adoption window, the three runtime seeds, the legacy-seed rule); warmup
  is declared, ordered, retained, unsalted; the run declares a positive
  concurrency outside the dedicated-Offline exemption; the summary carries
  output tokens, a positive TPOT P90 and at least the dataset's §12 acceptance
  count; at least one accuracy result is present; a dedicated Offline run meets
  §5.7.2 through `derived.offline_ordering`.
- **Per pareto** (`pareto.yaml`): §5.6's point cap; no point outside every
  region including the margin (`derived.out_of_range_points`).
- **Per system** (`system.yaml`): the §4.5.2 power declaration is present
  (advisory) and its `power_method` is Appendix E vocabulary.
- **Vocabulary** (from `valid_refs.yaml`): an `offline` value outside §8.3's
  three, a `region` outside its six, a steady-state verdict/status outside §4.4,
  a `load_pattern` outside §6.1 and a value of the wrong type are refused at
  collect time, so they are not repeated as rows.

## Not yet expressible

The dialect decides a row from one node's facts plus five named derivations. The
rules below need more than that; each is a candidate for a new derivation or
operator, not something a row can fake:

| Rule (as the CLI names it)                                                                                                                                                          | Why a row cannot decide it today                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Point count, region coverage (low/med/high/ultra-low), accuracy coverage across mandatory bands, accuracy run count `N`                                                             | needs a count of points (or of results) compared against `point_count_min` / `accuracy_run_count_requirement`, which are requirements, not counts                                                                                                                                                                                                                                                                                                             |
| Per-curve consistency: `load_pattern`, `dataset`, `seed_set`, `system_desc` agreement, `tps_utilization` reconciliation                                                             | needs aggregation over a curve's points (ours refuses agreement for `max_supported_concurrency`/`c_min_override` at load, the rest is unrepresented)                                                                                                                                                                                                                                                                                                          |
| Accuracy gates (`≥ 0.99 × golden`, fraction→percent rescaling, sample-weighted means across datasets)                                                                               | the catalog now ties each model to its accuracy set(s) (`accuracy_datasets`), records each set's run shape and accepts a per-set `targets` block beside the cumulative one, but a row cannot look a set up _by the model the run declares_: the join (`point.config.model_name` → `ruleset.models.<name>.accuracy_datasets.*`), the per-set lookup inside `accuracy_results.accuracy_scores`, the rescaling and the weighting are still beyond one comparison |
| §14 metric accounting (`completed + failed == issued`), `system_tps` vs `total/duration`, `tps_per_user` vs `1/P90`, `system_tps_per_kw`, maximal engagement, Appendix E arithmetic | needs arithmetic between facts, not one comparison                                                                                                                                                                                                                                                                                                                                                                                                            |
| Steady-state consistency (window ≥ 4 super-passes, drifting verdicts)                                                                                                               | needs the trend grid, not just the reported vocabulary                                                                                                                                                                                                                                                                                                                                                                                                        |
| Submission structure: `src/` + `docs/` + `src/<impl>/README.md`, `shared_src`/`shared_docs` path resolution, `point.yaml`-dirname agreement                                         | the walk reads `results/` only, and path resolution is a filesystem question                                                                                                                                                                                                                                                                                                                                                                                  |
| Drafter approval (§2.9.4)                                                                                                                                                           | needs the approved-drafter table and its two identification forms                                                                                                                                                                                                                                                                                                                                                                                             |
| Server-side streaming, warmup log archives, power-source verifiability                                                                                                              | explicitly not artifact-derivable (the CLI documents the same limits)                                                                                                                                                                                                                                                                                                                                                                                         |

What the loaders already refuse -- a missing
`system_desc.json`/`result_summary.json`/ `point.yaml` fact, a `<system>/` with
no models, a pareto with no runs, an entry no scope can reach, a malformed
manifest, a `c_min_override` §5.4 rejects, points disagreeing on
`max_supported_concurrency`/`c_min_override` -- needs no row here; those are
exit-2 refusals before any check runs.

## Known rough edges in this version

- The §12 floor rows key on `dataset_name` values spelled the way the submission
  checker's table spells them (`cnn_dailymail`, ...). A submission that spells a
  dataset differently gates the row off; extend the `when` list as spellings
  appear, or align the spelling.
- Vocabulary-only rules live in `valid_refs.yaml`: a value outside an allowlist
  is a collect-time refusal (exit 2) naming the fact, not a finding. The CLI
  reports the same facts as rules (exit 1) -- pick per taste.
- `point_warmup_salt_disabled` is gated on the field's presence: an omitted
  `salt` is §6.3.3's default (off) and passes silently, while the CLI warns on
  an explicit `true`.
- Accuracy gates are absent (see the table above), so a run with a weak accuracy
  score passes this cohort; only the presence of an accuracy result is checked.
  The catalog carries what a gate would need: the cumulative `accuracy_targets`,
  the `accuracy_datasets` tie naming the sets it is computed over (each set may
  declare its own `targets` in the same form, populated only where a reference
  threshold is published -- none is for this round's models, so only the
  cumulative gates exist), and the agentic gates' own `dataset`/`field` entries.
  The missing piece is the row dialect's join and per-set lookup, not the data.

- A nullable fact cannot carry a type: `link_to_model_transformation` is a
  string or an explicit `null`, and `type: str` refuses the null, so it stays
  undeclared (and therefore unnameable by rows) rather than mis-declared. A
  declaration form for "value or null" is a dialect gap.
- Percentile blocks are keyed by spelling: writers emit `"90.0"` where a row
  names `…percentiles.90`. `resolve` reads a numeric component against a key
  spelling the same number (the submission checker's canonicalisation), so the
  row finds it; a non-numeric percentile name would need its own row.
